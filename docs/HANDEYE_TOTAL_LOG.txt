Script and input file policy
----------------------------

中文：

脚本通过以下模式动态解析仓库根目录：

  SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
  PROJECT_ROOT="$(git -C "${SCRIPT_DIR}" rev-parse --show-toplevel 2>/dev/null || true)"

如果无法解析 git root，脚本会从自身位置按相对路径回退。

English:

Preserved troubleshooting notes
-------------------------------

中文：

`UR driver` 必须使用真实机器人运动学文件：

  configs/robot/ur5_actual_calibration.yaml

曾经出现的运动学不匹配报错原文：

  The calibration parameters of the connected robot don't match the ones from the given kinematics config file.

含义：`ROS driver` 使用的运动学与真实 `UR5` 不一致，会导致 `base -> tool0` 不准确，并放大 `hand-eye` 验证误差。

期望成功信息原文包括：

  Calibration checksum: calib_17294063568689657538
  Calibration checked successfully.
  System successfully started.
  Robot mode: RUNNING
  Safety mode: NORMAL

曾经出现的非致命消息原文：

  A message was lost!!!

含义：短暂运行 `ros2 topic echo` 时可能出现；如果 `/joint_states` 和 `base -> tool0` TF 正常，则不是失败。

曾经出现的真实失败原文：

  WARNING: topic [/joint_states] does not appear to be published yet
  Could not determine the type for the passed topic
  ERROR: /joint_states has no data yet.

含义：`UR driver` core node 未运行或已退出，导致 `/joint_states` 未发布。

曾经出现的 `UR driver` fatal error 原文：

  Could not get configuration package within timeout, are you connected to the robot?(Configured timeout: 1 sec)

含义：driver 部分连接到机器人，但没有及时收到 robot configuration package。重启 `UR driver`，并确认 teach pendant 上的 `External Control` 程序处于 Play 状态。

English:

The `UR driver` must use the real robot kinematics file:

  configs/robot/ur5_actual_calibration.yaml

Previously observed kinematics mismatch text:

  The calibration parameters of the connected robot don't match the ones from the given kinematics config file.

Meaning: the `ROS driver` was using kinematics that did not match the physical `UR5`, which can make `base -> tool0` inaccurate and increase `hand-eye` validation error.

Expected successful messages include:

  Calibration checksum: calib_17294063568689657538
  Calibration checked successfully.
  System successfully started.
  Robot mode: RUNNING
  Safety mode: NORMAL

Previously observed non-fatal message:

  A message was lost!!!

Meaning: this can appear when `ros2 topic echo` subscribes briefly. It is not a failure if `/joint_states` and `base -> tool0` TF are valid.

Previously observed real failure:

  WARNING: topic [/joint_states] does not appear to be published yet
  Could not determine the type for the passed topic
  ERROR: /joint_states has no data yet.

Meaning: the `UR driver` core node was not running or had exited, so `/joint_states` was not being published.

Previously observed `UR driver` fatal error:

  Could not get configuration package within timeout, are you connected to the robot?(Configured timeout: 1 sec)

Meaning: the driver partially connected to the robot but did not receive the robot configuration package quickly enough. Restart `UR driver` and confirm that the `External Control` program is playing on the teach pendant.
