Robot driver and kinematics
---------------------------

The first UR driver runs showed a kinematics mismatch:

  The calibration parameters of the connected robot don't match the ones from the given kinematics config file.

Meaning:

  The ROS driver was using kinematics that did not match the physical UR5.
  That can make base -> tool0 inaccurate and can cause large hand-eye validation error.

Fix performed:

  Extracted real robot calibration from 192.168.1.10.
  Saved it to /home/z/Apps-my/ur5_actual_calibration.yaml.
  Updated /home/z/Apps-my/start_ur5_driver.sh to pass:

    kinematics_params_file:=/home/z/Apps-my/ur5_actual_calibration.yaml

Startup troubleshooting notes
-----------------------------

Observed non-fatal message:

  A message was lost!!!

Meaning:

  This can appear when ros2 topic echo subscribes briefly. It is not a failure if
  /joint_states data and base -> tool0 TF are printed afterwards.

Observed real failure:

  WARNING: topic [/joint_states] does not appear to be published yet
  Could not determine the type for the passed topic
  ERROR: /joint_states has no data yet.

Cause found:

  UR driver core node was not running or had exited, so /joint_states was not
  being published.

Observed UR driver fatal error:

  Could not get configuration package within timeout, are you connected to the robot?(Configured timeout: 1 sec)

Meaning:

  The driver connected partially but did not receive the robot configuration
  package quickly enough. Restarting the UR driver and confirming teach pendant
  External Control solved it.
